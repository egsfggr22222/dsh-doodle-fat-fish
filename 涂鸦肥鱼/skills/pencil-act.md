# 截图任务 —— pencil act

---

# 零、进入钩子（硬闸门）

**本技能只在一种情况下加载：消息开头带【托盘呼唤】，并且附了整屏截图。**

没有【托盘呼唤】——不加载，不画，不碰画板。

同时这是**唯一**允许在屏幕上画的入口。除它之外，只有两种情况能画：

| 允许 | 例子 |
|---|---|
| 本条消息明确要求画 | 「画在屏幕上」「标一下」「圈出来」 |
| 本条消息发图并要求标注 | 「找出图中的马」「标注鸡」 |

**以下绝对不能画：**

| 情况 | 例子 | 该做什么 |
|---|---|---|
| 只是问问题 | 「这是什么」 | 只在聊天里答 |
| 让改代码 / 加功能 | 「托盘加个一键清除」 | 只改文件 |
| 讨论流程 / 规则 | 「你要先 xx 再 yy」 | 只回话，把规则写进 skill |
| 自己觉得画出来更清楚 | —— | 不画 |
| 上一轮让画过 | —— | 这一轮的许可不延续 |

「口头答应了用户」**不构成许可**。答应的是改 skill / 改代码，不是获得永久作画权。

**违反这条 = 这一轮做错了**，不是风格问题。

# 用户按下托盘「呼唤 agent」，就会截一张整屏发给我。

**这类图片永远走这个流程，不走 `dsh-companion`。**

---

# 名字

| 叫法 | 来源 | 流程 |
|---|---|---|
| `pict act` | 用户直接把图片发给我，要我标注 / 找东西 | `dsh-companion` |
| `pencil act` | 托盘「呼唤 agent」的截图 | 本文件 |

---

# 一句话

```
材料进 → 我看 → 决定 → 发指令 → 屏幕出图 → 材料消失
```

`act.png` 只是**给我看的一次性材料**。真正交付的是我发给程序的那组绘制指令。

**不保存任何东西。** 没有最终图，没有归档，没有历史。屏幕上画出来就完事。

---

# 第一步：图片落盘

截图已经在附件里，先拿到可读路径：

```
now-image
```

返回 `path`。后续 `find` 的 `image` 参数用它。

---

# 第二步：一条命令拿材料

```
find { method: "act", image: "<now-image 给的 path>", task: "pencil-<短名>" }
```

这一条命令自动跑完（我不参与中间过程）：

1. 差分位移 → 版面分块
2. OCR 在原图上识别文字
3. UI 检测在原图上识别可交互元素
4. 把文字按块归属合并，连同块号、UI 框一起标到差分图上

返回一张 `act.png`（在系统临时目录，看完即弃）。

返回里还带结构化数据，**这些才是判断依据**：

| 字段 | 内容 |
|---|---|
| `matches` | 差分块表：每块的 id 和坐标 |
| `texts` | 文字层：坐标 + 原文 |
| `uis` | UI 层：坐标 |

---

# 第三步：看 act.png（只看一次）

```
read_image "<返回的 path>"
```

图上：

| 元素 | 含义 |
|---|---|
| 蓝框 + 蓝数字 | 差分块，数字是块号 |
| 蓝细框 | UI 可交互元素 |
| 红字 + 米底 | 这一块里识别到的文字 |

**看一眼就够。** 不放大、不切块、不反复调看。

---

# 第四步：我自己判断要画什么

这一步是 `pencil act` 的核心，也是**只有我能做的一步**。

看完 `act.png` 上的三样东西（差分块 + OCR 文字 + UI 框），我决定：

| 决定 | 例子 |
|---|---|
| 框哪一块 | 「这行字就是他问的那句，框住」 |
| 在哪写字 | 「在这块下面写答案」 |
| 画不画箭头 | 「从这个按钮指向那块文字」 |
| 什么颜色 | 蓝、绿、黄都行，**不能用红** |

**程序不做这个判断。** 它只按我给的坐标和形状画。

---

# 第五步：发指令，屏幕出图

```
pencil {
  action: "draw",
  items: [ ... 我要画的 ... ]
}
```

| 我发什么 | 说明 |
|---|---|
| **画什么** | `items` 里的图元：框、箭头、文字 |
| **位置** | 每个图元的 `x` / `y`，**直接取网格上的数字** |

## 坐标只从网格读，不换算

`act.png` 上每 100 像素一条线，四条边都标着数字。**那些数字就是真实桌面坐标。**

读法：找到目标 → 看它压在 x 哪两条线之间、y 哪两条之间 → 取中间值。

```
目标在 x=1200 与 1300 之间偏左、y=500 与 600 之间居中
→ 发 {x:1225, y:550}
```

**没有 `view`，没有缩放，没有系数。** 读到什么就发什么，程序原样画。

之前有过一套 `view` 换算（申报「我那张图多大」，程序乘系数）—— 那是多余的，
而且会造成双重缩放：网格读数 1225 再乘 1.25 变成 1531，整体偏 25%。
已经整个删掉了。

## 形状

框：`{"type":"rect","x":100,"y":200,"w":300,"h":80}`
圆：`{"type":"ellipse","x":..,"y":..,"w":..,"h":..}`
箭头：`{"type":"arrow","x1":..,"y1":..,"x2":..,"y2":..}`
文字：`{"type":"text","x":..,"y":..,"text":"..","size":18,"color":"#00e0ff"}`
线段：`{"type":"path","points":[[x,y],...]}`

## 格式硬规则（违反 = 整批丢弃，屏幕什么都不出现）

程序的格式校验是严格匹配，不合格的图元**静默丢弃**；整批全不合格就报
`draw needs at least one drawable primitive in 'items'`。以下是对照校验代码逐条验证过的：

**七种合法类型**：`rect` `ellipse` `path` `arrow` `text` `image` `pixels`——逐字匹配，
`circle` 这类自造名字直接丢。圆 = `ellipse`（x,y,w,h 是外接框，即 w==h）。

**会被丢弃的写法**（已验证）：

| ❌ 丢弃 | ✅ 接受 |
|---|---|
| `{"type":"rect","x":"530",...}` 坐标加引号 | 坐标必须是**数字**：`{"x":530}` |
| `{"type":"circle","cx":..,"r":..}` 自造类型 | 七种名字之一，逐字匹配 |
| `{"type":"text","text":"",...}` 空文字 | 非空文字；不想写字就不发这个元素 |
| `pencil { action:"draw", type:"rect", x:.. }` 字段放外层 | 图元必须装在 `items` 数组里 |

**宽松的部分**（不会失败，别担心）：`w` 和 `width`、`h` 和 `height` 等价；
path 的点既吃 `[[x,y],...]` 也吃 `[{"x":..,"y":..},...]`；
颜色吃 `#rgb`、`rgba(...)` 和英文色名。

发出前自查三条：**每个元素的 `type` 是七种之一？坐标全是数字不带引号？`items` 是数组？**
三条都对再发。报了 `needs at least one drawable primitive` 就是这里错了，
**改格式重发**，不要换工具、不要截图分析。

**我的笔迹不用红色** —— 红色是用户的专属色。

# 第六步：完事

屏幕画出来就结束了。

| 不做 | 原因 |
|---|---|
| 不存最终图 | 屏幕上已经画出来了，用户看得见 |
| 不归档 | 这不是「标注图片」任务，没有图片产物 |
| 不写历史 | 同上 |
| 不调 `finish` | `finish` 是 `pict act` 用的，本流程不需要 |
| 不复述 act.png 内容 | 用户也看得见屏幕 |

`act.png` 在系统临时目录，会被下次清理掉。不用管它。

# 他的原话在画板上

用户可能在看屏幕而不是聊天窗，所以第 4 步决定画什么之前，先读一遍他在画板上写了什么：

```
pencil scene
```

- `strokes` 是他的红线：跟 `points` 走一遍就知道他圈了哪块
- `texts` 是他打的字，**这是他的原话**

他的红圈 = 「这个」，红箭头 = 「那个方向」，红字 = 他的问题。

这是**读**，不是画 —— 读不受闸门限制。

# 禁止

| 禁止 | 原因 |
|---|---|
| **没有【托盘呼唤】/ 没被要求就画** | 见开头闸门，这是准入条件不是风格 |
| **自己 `eye` 截图再画** | 材料只从 `find act` 来，截图是另一条路 |
| **`PIL` / 脚本裁剪、放大、切块** | 「看不懂就放大」是走远路，禁令里写着 |
| **自己看原图估坐标** | 只读 `act.png`（它已经把 OCR/UI/差分叠好了） |
| 分步跑 `scan` 再跑 `blocks` | `act` 一条命令就够 |
| `find { method: "zoom" }` / `grid` | 截图流程不允许放大细找 |
| 读原图（附件原文件） | 只读 `act.png` |
| 申报 view / 自己乘系数 | 网格数字就是真实坐标，换算只会让它偏 |
| 保存 `act.png` / 出最终图 / 归档 | 屏幕上画完就结束，没有图片产物 |
| 写脚本查窗口 / 读注册表 / 算像素 | 走远路，用户看着更困惑 |

---

# 校验最多三次

允许画的情况下，画完可以截图看一眼，**最多三次**。大致对了就停下回话。

不要一遍遍擦掉重画追几个像素 —— 用户一直在等，越改越乱。
