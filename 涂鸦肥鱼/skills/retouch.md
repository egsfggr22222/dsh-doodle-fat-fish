# DSH 伴随者 · 补标

---

# 零、钩子

## 进入钩子

**有且只有一种情况加载本技能：用户对上一次交付的标注结果表达明确的不满或异议。**

明确不满，指用户的话里指出上一次结果有问题：

| 用户说 | 判定 |
|---|---|
| 「漏了」「这里还有」「没标全」「还有别的」 | 加载 |
| 「这个框偏了」「位置不对」「框大了 / 小了」 | 加载 |
| 「标错了」「标到别的地方去了」 | 加载 |
| 「重来」「重新标」「再来一次」 | 加载 |
| 「这里看不清」 | 加载 |

## 不触发

下列任一情况，**一律不加载，不动作，不重标**：

| 用户说 | 判定 |
|---|---|
| 「好」「嗯」「可以」「收到」「谢谢」 | 不加载 |
| 用户提出新问题、新任务 | 不加载 |
| 用户发来一张新图片 | 不加载（走 `dsh-companion`） |
| 用户继续原来的话题，没有评价上一次结果 | 不加载 |
| 用户只是复述要求，没说上次哪里不对 | 不加载 |

判不准时，按「不加载」处理。

## 退出钩子

`finish` 返回 `ok: true` 的那一刻，本流程结束。

结束后禁止再调用 `find`、`mark`、`read_image`；禁止继续追查；直接交付，等用户回话。

---

# 一、本技能独有的权限

**带坐标网格的原图，只在本技能里出现。**

主流程（`dsh-companion`）只能看 `diff.png` 一眼、不许放大、不许追精度。本技能相反：

| 允许 | 内容 |
|---|---|
| `read_image` 原图 | 可以看，而且应该看 |
| `find { method: "grid" }` | 带坐标系的原图，仔细看 |
| `find { method: "zoom" }` | 放大到某个区域，仔细看 |
| 反复看 | 看到看清楚为止 |

主流程的「快」在这里不适用 —— 补标本来就是慢工。

---

# 二、执行流程

```
第 1 步  从用户的话里取出：哪一处、什么问题
第 2 步  read_image 原图                  看清整体
第 3 步  find { method: "grid", image: "<原图>", gridSize: 75 }
         read_image <grid.png>            带坐标系的原图，仔细看
第 4 步  需要更准 → find { method: "zoom", ... } → read_image <zoom.png>
第 5 步  mark { task, image, blockIds: [...], shapes: [...] }
         或 mark { task, reset: true } 后重标
第 6 步  finish { task }
第 7 步  交付
```

`task` 与 `image` 用上一次交付时的那一对，不新开任务。

第 2、3 步都要做：原图看质感，网格图读坐标。只看原图读不准数，只看网格图看不出哪里是目标。

---

# 三、第 1 步：取意见

只听用户这一句话，取出两件事：

1. **哪一处** —— 位置、目标名、或用户圈出的区域
2. **什么问题** —— 漏了 / 偏了 / 错了 / 看不清

用户没指出具体位置的，按「全盘重做」处理。

---

# 四、第 2 步：read_image 原图

```
read_image "<原图>"
```

看图，判断用户说的是哪一块。这一步只建立整体印象，不在这里读数字。

---

# 五、第 3 步：grid

```
find { method: "grid", image: "<原图>", gridSize: 75, task: "<task>" }
read_image "<返回的 grid.png>"
```

网格标签就是原图坐标，直接读，不用换算。目标分散时用这一步。

---

# 六、第 4 步：zoom

只在需要更准坐标时用：

```
find { method: "zoom", image: "<原图>", cx: <x>, cy: <y>, factor: 4, task: "<task>" }
read_image "<返回的 zoom.png>"
```

`cx` `cy` 用原图坐标。不够细用 `factor: 8`。

## 限制

1. 只放大用户指出的那一处
2. 一次意见最多放大 3 次
3. 不对每个目标各放大一次

---

# 七、第 5 步：mark

## 补框

```
mark { task, image, blockIds: [新增的块号], shapes: [新增的框] }
```

只提交新增的。已提交过的不重复提交。

`blockIds` 与 `shapes` 可以同时用：差分块框住的引用块号，没框住的按网格图上的坐标手写。

## 全盘重做

```
mark { task, reset: true }
```

然后重新提交全部框。

## shapes 写法

框，xywh：

```json
{"kind":"box","x":957,"y":565,"w":80,"h":104}
```

框，四点：

```json
{"kind":"box","points":[[375,450],[600,450],[600,675],[375,675]]}
```

圆：`{"kind":"circle","center":[997,616],"circumference":251}`
文字：`{"kind":"text","x":100,"y":200,"text":"内容","size":20}`
点：`{"kind":"dot","x":500,"y":300}`

不传 `stroke`。

---

# 八、第 6 步：finish

```
finish { task }
```

累计 shapes 一次画到原图，输出最终图进 `history/`，清空 `work/`，源图进 `sources/`。

返回 `ok: true` 即触发退出钩子。

---

# 九、第 7 步：交付

```
第一行：<原标题> · 已按你的意见修改

![<原标题>](<最终图路径>)

| 位置 | 内容 |
|---|---|
| ... | ... |

最终图：`<最终图路径>`
```

交付后停手，等用户回话。

---

# 十、禁止

- 用 bash 或 python 切图、扫像素、算连通域
- 重复提交已提交过的框
- 用户指出一处却放大全部目标
- 超出用户意见范围改别的框
- 用户没提明确不满就加载本技能
- 交付后自行追查遗漏
